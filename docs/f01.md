# F01 behavior and decisions

## Source policy

Reviewed on 2026-10-28 against the [API reference](https://himalayas.app/docs/remote-jobs-api)
and [OpenAPI specification](https://himalayas.app/docs/openapi.json).
The provider permits personal and commercial display with attribution, requires the original
`applicationLink`, prohibits onward distribution to job boards/aggregators or JobPosting feeds,
and asks integrations to remove closed/expired listings from active display. The source policy
stored by `source-init` records these rules and the 24-hour polling interval. It is disabled by
default. This review records the published integration rules, not a general legal clearance.

Optional free API keys have a documented allowance of 60 requests per minute and 10000 per UTC day.
Anonymous requests share a public allowance. Every local HTTP attempt, including retries and status
checks, counts toward the local request budget regardless of upstream caching. Successful responses
do not provide rate limit headers. The single-job endpoint may cache status for ten minutes.

Search uses numbered pages and stops only on an empty `jobs` array. Short pages and `totalCount`
do not terminate the walk. Search results can shift between pages. The pipeline deduplicates on
`guid` but cannot guarantee exhaustive coverage from a moving page-number feed.

## Component boundaries

`career-radar ingest` calls `run_ingestion(engine, settings)`. The ingestion service owns source
policy admission, lock lifetime, run records, deduplication, upserts, and lifecycle changes.
`HimalayasClient.search(query)` owns transport, retry timing, pagination, and request accounting.
Pure functions in `rules` own provider validation, title classification, normalization, and geography.
FastAPI reads SQLAlchemy models and exposes separate Pydantic response schemas.

The architecture review compared page-by-page transactions with a bounded in-memory collection
followed by one atomic write. F01 uses the latter to keep HTTP waits outside transactions and avoid
checkpoint coordination. This may retain several thousand bounded results in memory. Introduce
page checkpoints if measured run size makes that unacceptable. The initial run record commits
before fetching. A successful result batch and its final counts commit together. A database failure
rolls back the entire batch, then records failure in a separate transaction. If the database is
unreachable during finalization, the run can remain `running`; the next admitted run marks it failed.

MySQL `GET_LOCK` serializes ingestion across processes using a dedicated connection. It is released
on that same connection in `finally`. Unique database constraints remain the final deduplication
protection. SQLite is only used for fast tests and is rejected by the public ingestion service.

## Data and status semantics

Timestamps use UTC on the wire. A SQLAlchemy type writes naive UTC to MySQL DATETIME and restores
UTC on read, rejecting naive application datetimes. `provider_updated_at` comes from `pubDate`.
`posted_at` stays null because the provider does not supply an original posting date.
`provider_expires_at` comes from `expiryDate`, which is a listing expiry rather than an employer
deadline. Salary values retain their provider period and currency and use Decimal storage.

A valid feed observation verifies an open record only as of that observation. Expired records leave
active results immediately. Due records not observed in searches receive bounded single-job checks:
200 refreshes data, 410 closes, and 404 makes status unknown. Network failures never close records.
The API omits records verified more than 24 hours ago from active results and reports them as stale
on detail responses. Geography and timezone evidence remain independent from work authorization.

The provider defines empty location and timezone arrays as worldwide and unrestricted respectively.
Missing arrays are unknown. Country matching accepts documented ISO `alpha2` objects and observed country-name strings,
using the pycountry ISO dataset. Numeric offsets include fractional hours. Unsupported restriction shapes or
unparseable offsets remain unknown. The pipeline retains incompatible records for explicit browsing
and preserves original restrictions. Default active results can include unknown or incompatible
geography; clients can request the compatibility filter to narrow them.

Descriptions are untrusted plain text after HTML tag removal. No description URL is fetched.
Application URLs and provider identities must be HTTPS Himalayas job links and are preserved exactly.
Requests target a fixed API origin and do not follow redirects. Diagnostics use safe error categories,
not raw HTTP responses, exception strings from database drivers, or credentials.

## Limits and future operations

F01 is manual and private. A later scheduler can invoke the CLI once per day, or call the same service
from a dedicated process. It must honor the same database lock, source policy, and polling interval.
No scheduler belongs in FastAPI startup or request handlers.

Default searches filter by provider entry/mid values and use separate internship queries without
seniority filtering. Non-intern jobs with omitted provider seniority may be missed by upstream
filtering. Title matching covers configured phrases and common frontend/backend/fullstack variants;
it is deterministic and conservative, rather than a semantic or AI classifier.

Run `ruff`, `mypy`, and `pytest` as described in the README. Live MySQL requires a running database,
and live Himalayas checks require network access. The implementation report records what was
actually exercised. Do not treat mock fixtures as evidence of current provider job availability.

The live search contract check on 2026-10-28 found country-name strings and numeric timezone offsets,
although the published schema describes country objects and string offsets. The adapter accepts both
shapes and tests preserve the observed values. This discrepancy is evidence from a live response,
not an assumption about undocumented provider fields.
